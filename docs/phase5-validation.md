## Run without Gradle

Requires Python 3.10+ with standard-library `sqlite3`; no pip packages or network.
Run these from the repository root:

```sh
python3 -B -m unittest discover -s scripts -p 'test_phase5_*.py'
python3 -B scripts/validate-phase5.py
python3 -B scripts/validate-phase5.py --benchmark
```

The first command tests the validator and executes the actual rename SQL against
synthetic SQLite fixtures. It does **not** execute the Kotlin/Room test suite.
The validator prints to stdout and writes no artifacts or database files. Add
`--json` for full input hashes, sample timings and workload limits. `--root` can
inspect another trusted checkout; its captured checker modules are the modules
executed, and a changed driver requires restarting with the matching script.

Exit status is deliberately not a blanket green check:

| Exit | Meaning |
| --- | --- |
| `0` | Recognized checks passed; not release approval. |
| `1` | A concrete failure, unsupported/broken input, or concurrent edit invalidated the run. |
| `2` | Manual/runtime verification remains; no recognized concrete failure. |

Review findings are expected: this tool cannot establish Android acceptance.
Do not suppress a nonzero exit just to mark Phase 5 complete.

### Concurrency and resource limits

- Capture public Kotlin source/test files, the current/previous Room exports and
  checker modules into memory; hash them with SHA-256 and check for changed,
  added or removed inputs afterwards. A run can only attest to its captured
  snapshot, not edits made after it exits. No checkout, stash, staging or commit.
- Execute captured checker modules, not a possibly stale pre-imported revision.
  The manifest's aggregate hash is printed; JSON output includes individual
  hashes. No database contents, credentials or source payloads are reported.
- Refuse symlinked/out-of-workspace inputs. Snapshot reads are capped at 2 MB per
  file, 2,000 files and 32 MB total. Generated bytecode is avoided with `-B`.
- SQL checks use in-memory SQLite, restricted query authorization, statement,
  page and VM-work limits. No user database or Android Keystore is opened.
- The optional benchmark bounds scalar data and page allocation below 8 MiB,
  rows below 10,000, with an eight-second cooperative deadline and VM-step cap.
  It is sequential and opt-in, not a stress test.

## What is implemented

### Data-preserving rename and targeted writes

`ConversationRepository.renameConversation()` formerly called an
`@Insert(REPLACE)` on the conversation parent. SQLite replacement deletes that
parent first, so cascading foreign keys can remove messages, versions, files,
summary and recovery/quarantine rows. Rename now executes a scoped
`UPDATE conversations SET title, updatedAt WHERE id` within the existing IO,
mutex and transaction boundary. A missing ID remains a no-op.

- Added query: `app/src/main/kotlin/org/starfall/multigateway/shared/storage/database/dao/Daos.kt`.
- Updated caller: `app/src/main/kotlin/org/starfall/multigateway/shared/storage/ConversationRepository.kt`.
- Executed offline regression: `scripts/test_phase5_rename.py` checks every
  synthetic child table, unrelated conversations, FK integrity and missing IDs.
- Added and run: `app/src/test/java/org/starfall/multigateway/ConversationRenameIntegrityTest.kt`
  covers repository reloads, ordered versions, tool/file references, summary and
  retained migration errors under Room/Robolectric.

`ConversationRepository.saveConversation()` now upserts conversation metadata
without `REPLACE`, removes only deleted messages/versions/activities/files, and
updates or inserts only changed entities. `ConversationIncrementalPersistenceTest`
checks that an append and an edit preserve unchanged message/version/activity
rowids.

### Validation tooling

| File | Purpose |
| --- | --- |
| `scripts/validate-phase5.py` | Snapshot, source/schema/query checks, optional benchmark and truthful exit status. |
| `scripts/phase5_source.py` | JSON-column/serialization inventory, metadata-mapping source guards, migration registration and unfinished full-history-write checks. |
| `scripts/phase5_sqlite.py` | Compare extracted DDL with Room export; execute actual DAO SELECTs, inspect indexed query plans and probe FK enforcement. |
| `scripts/phase5_fixtures.py` | Independent message/summary/quarantine flags and grouped/NULL-group provider cases. |
| `scripts/phase5_benchmark.py` | Bounded synthetic workload and raw host SQLite timings/VM steps. |
| `scripts/test_phase5_*.py` | Guard regressions, schema mismatch/omitted-DDL tests, forbidden metadata reads, benchmark bounds, snapshot-code binding and rename preservation. |

DDL comparison covers columns, nullability/defaults/PK order, indexes and foreign
keys. The previous export identifies new/changed tables that need migration DDL;
deleting a whole CREATE statement must not silently remove its coverage. Literal
ALTER paths and interpolated SQL require review. Matching DDL is **not proof the
Kotlin migration invokes it or preserves legacy rows**. Room identity/schema
generation, partial-index predicate equivalence and all prior-version upgrade
paths still require the real migration suites.

Metadata SELECTs execute with an SQLite authorizer that rejects body, raw
quarantine payload and auth-table reads, including joins/subqueries. Public
`authId` references and the `multipleApiKeys` Boolean policy are not secret values.
Source inspection separately follows recognized list mapper helpers; it is
heuristic, not proof against dynamic dispatch or alternate serialization.

## Remaining JSON boundaries: reviewed inventory

The observed export has no normal `*Json` blob columns. This is a name-based
guard, not a claim that arbitrary TEXT values could never contain JSON.

| Remaining occurrence | Justification / required follow-up |
| --- | --- |
| `ProviderStorageMapper.kt` encrypted `encodeToString(payload)` | `ProviderAuthPayload`: authorization, headers, proxy credentials, API keys/OAuth accounts and private endpoint forms. Immediately wrapped in `SecretCipher.encrypt`; non-secret model configuration uses relational rows. Runtime auth-isolation tests pass. |
| `McpRepository.kt` encrypted `encodeToString(payload)` | `McpAuthPayload`: authorization, headers and private URL. Same encrypted-auth exception; not serialization of the whole server record. Runtime auth-isolation tests pass. |
| `ConfigurationMigration10Json.kt` → `migrationEncryptedPayload()` | Used by provider/MCP migration helpers for their encrypted auth payloads. Migration source decoding and encrypted recovery handling must remain until supported upgrades no longer need them. |
| `conversation_migration_quarantine.rawJson` | Original undecodable historical data retained for recovery, not canonical application storage. Never expose its values in validator output. |
| `configuration_migration_quarantine.rawValue` | Configuration recovery payload, not normal configuration. Encryption and recovery fidelity require real migration tests. |
| `SecretCipher.kt` Base64 `encodeToString` | Binary authenticated-cipher envelope encoding, not JSON object/list persistence. |
| `preferences/AppPreferencesRepository.kt` | Sidebar and prompt-library JSON in DataStore, explicitly outside this Room migration. |
| `preferences/ModelConfigurationMemory.kt` | Configuration templates in preferences, not migrated Room tables. |
| `preferences/ToolSettingsStore.kt` | Tool-setting preference boundary, not Room canonical storage. |
| `StructuredJsonStorage.kt` and `structured_json_*` tables | In-memory JSON is mapped to ordered typed node rows; objects/lists are not stored as one JSON string. Validate node ownership, null/empty/numeric fidelity and orphan cleanup in repository tests. |
| API/request parsers and app-data import/export serializers | External formats must remain compatible; deleting their serializers is not Phase 5 cleanup. Export must explicitly resolve credentials and histories rather than silently exporting metadata-only models. |

The validator intentionally leaves encrypted serialization as `REVIEW` so a
future addition of non-secret application structures to an auth payload cannot
be excused just because encryption occurs nearby.

### Synthetic scaling observations (not startup measurements)

Runtime: CPython 3.13.5, SQLite 3.46.1, Linux. Nine conversation metadata rows
were held fixed. Each new message had one 2,048-byte version body. Five timed
samples followed one warmup; VM-step counts were collected in separate runs.
Timing includes Python scalar accounting and is subject to host scheduling.

| Workload | Total message-body bytes | Metadata rows / bytes / VM steps | Selected envelope rows / bytes / VM steps | Metadata median ms | Selected median ms |
| --- | ---: | --- | --- | ---: | ---: |
| Baseline | 16,384 | 9 / 1,494 / 973 | 2 / 138 / 31 | 0.637776 | 0.091379 |
| Add 512 unrelated messages | 1,064,960 | 9 / 1,494 / 973 | 2 / 138 / 31 | 0.556223 | 0.064925 |
| Grow selected conversation to 64 messages | 1,191,936 | 9 / 1,494 / 973 | 64 / 4,654 / 589 | 0.550584 | 0.516906 |

Metadata and selected-envelope result fingerprints did not change after unrelated
history growth. The selected read grew only when selected messages were added.
`getMessages()` returns message envelopes, **not complete versions/bodies**;
these numbers do not measure full-conversation repository loading, legacy-to-new
speedup, cold-start UI readiness, first-send latency, Android storage I/O or
Keystore work. No noisy timing ratio is a pass/fail threshold.

6. **Post-migration inspection:** verify `foreign_key_check`, indexes, ordered
   message/version/tool/file counts, broken profile/provider links, duplicate
   versions, missing attachment files and structured-document/auth orphans.
   Synthetic FK probes cannot establish real migration fidelity or file presence.

Until those items have evidence, Phase 5 remains partial. The host validator also
has known concrete DDL-recognition failures because Kotlin-generated migration
SQL is not statically visible to it. Preserve unrelated agents' changes and do
not commit the shared worktree without explicit authorization.
